# 04 工具选型表

> "有什么可用"的全景工具箱。决策树的第 0 步 / 第 1 步告诉你"按症状抓哪一个"，本表告诉你"有哪些可抓"。
> 本文转录自 spec §4「通用定位手段（工具选型工具箱）」。

## 总览（9 类 → 一句话用途）

| # | 类别 | 一句话用途 |
|---|------|-----------|
| 1 | 内核启动/调试参数 | 改内核启动行为，抓 oops/挂死现场 |
| 2 | 编译期调试选项（Kconfig） | 编译期把检测器编进去 |
| 3 | 动态调试（dyndbg） | 运行时按模块/文件/行开关 printk |
| 4 | 追踪设施 | 运行时观测函数/事件流 |
| 5 | 事后分析 | 崩溃后解码 oops / 分析 vmcore |
| 6 | 交互调试 | kgdb / kdb 单步内核 |
| 7 | 静态分析 | 不改代码就查潜在缺陷 |
| 8 | 挂死检测 | 抓 softlockup/hardlockup/rcu stall |
| 9 | SysRq 魔术键 | 系统挂死时保命 dump |

## 1. 内核启动/调试参数

| 参数 | 作用 |
|------|------|
| `loglevel=N` | 控制台日志级别（0=仅紧急 … 7=全开）；调试常用 `loglevel=7` |
| `ignore_loglevel` | 忽略所有 loglevel 限制，全量打印 |
| `debug` | 开启内核调试输出 |
| `dyndbg="module foo +p"` | 启动时按模块/文件开启动态调试 |
| `panic_on_oops=1` / `oops=panic` | oops 直接 panic（配合 kdump 抓现场） |
| `panic=N` | panic 后 N 秒自动重启 |
| `ftrace_dump_on_oops` | oops/panic 时 dump ftrace 环形缓冲，抓崩溃前函数轨迹 |
| `kptr_restrict=0` / `no_hash_pointers` | 日志显示真实内核指针（解 oops 地址必需，默认会打码） |
| `softlockup_panic=1` / `hung_task_panic=1` | 挂死时 panic |
| `softlockup_all_cpu_backtrace=1` | softlockup 时回显所有 CPU 栈 |
| `nmi_watchdog=1` | NMI 看门狗，抓硬锁死 |
| `earlycon` / `earlyprintk` | 早期启动输出（early boot 崩溃用） |
| `initcall_debug` | 打印每个 initcall 耗时，定位启动挂死 |
| `slub_debug=...` / `page_poison=1` / `slab_nomerge` | 内存调试参数 |
| `init_on_alloc=1` / `init_on_free=1` | 分配/释放自动填充，抓未初始化使用 |
| `page_owner=on` | 启动即开启 page_owner，查内存流动/谁分配的 |
| `no_console_suspend` | 挂起时保留控制台 |
| `nokaslr` | 关 KASLR，便于地址映射 |
| `maxcpus=1` / `nosmp` | 限 CPU 数，缩小竞态复现范围 |
| `crashkernel=...` | 预留 kdump 内存 |

## 2. 编译期调试选项（Kconfig）

| 选项 | 作用 |
|------|------|
| `CONFIG_DEBUG_KERNEL` / `DEBUG_INFO` / `FRAME_POINTER` | 调试信息基础 |
| `CONFIG_KALLSYMS` | oops 里能解析符号名 |
| `CONFIG_DYNAMIC_DEBUG` | 运行时按模块/文件开关 printk（dyndbg） |
| `CONFIG_PROVE_LOCKING`(lockdep) / `DEBUG_ATOMIC_SLEEP` / `DEBUG_SPINLOCK` | 锁正确性 |
| `CONFIG_DEBUG_LIST` / `DEBUG_VM` / `DEBUG_SG` | 数据结构完整性 |
| KASAN / KCSAN / KMSAN / UBSAN / KFENCE / PAGE_OWNER / KMEMLEAK / SLUB_DEBUG | 内存/竞态检测 |
| `CONFIG_RCU_CPU_STALL_TIMEOUT` | RCU stall 检测 |
| `CONFIG_LOCKUP_DETECTOR` | softlockup/hardlockup 检测器本体 |
| `CONFIG_DETECT_HUNG_TASK` | hung task 检测 |
| `CONFIG_DEBUG_STACKOVERFLOW` / `DEBUG_STACK_USAGE` | 栈溢出 / 栈用量检测 |
| `CONFIG_DEBUG_PAGEALLOC` | 页分配器调试（unmap 释放页，抓 UAF） |
| `CONFIG_DEBUG_OBJECTS` | 对象生命周期调试（timer/workqueue/rcu 误用） |
| `CONFIG_SCHED_STACK_END_CHECK` | 调度时检查栈越界 |

## 3. 动态调试（dyndbg）

开 `CONFIG_DYNAMIC_DEBUG` 后，运行时 `echo 'module foo +p' > /sys/kernel/debug/dynamic_debug/control` 按模块/文件/行开关 printk，不用重编。

## 4. 追踪设施

- **ftrace**（function / function_graph tracer，配 `trace-cmd`）
- **tracepoints / events**（`/sys/kernel/tracing/events/`）
- **kprobes / kretprobes**（动态插桩任意函数）
- **eBPF / bpftrace**（低开销动态追踪）
- **perf**（`perf record` / `perf probe`）
- **延迟/噪声 tracer**：`osnoise`（系统噪声）、`timerlat`（调度延迟）、`hwlat`（SMI/硬件噪声）；`irqsoff`/`preemptirqsoff`（关中断/关抢占最长时间）→ 详见 `methodology/16-延迟分析RT.md`、`15-中断与软中断分析.md`

## 5. 事后分析

- oops 解码：`scripts/decode_stacktrace.sh`、`scripts/faddr2line`
- `crash vmlinux vmcore`、`drgn`（分析 vmcore）
- `pstore`（重启后保留崩溃日志）
- kdump / kexec

## 6. 交互调试

- `kgdb`（gdb over serial）、`kdb`（内核内置调试器）

## 7. 静态分析

- Sparse、Smatch、Coccinelle、clang analyzer、`checkpatch.pl`

## 8. 挂死检测

- softlockup / hardlockup detector、hung_task、RCU stall、NMI watchdog

## 9. SysRq 魔术键（系统挂死时的保命手段）

- `t`(dump 任务)、`w`(dump 阻塞任务)、`m`(内存信息)、`l`(所有 CPU backtrace)
