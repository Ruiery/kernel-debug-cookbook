# 08 数据竞态排查

> 决策树第 1 步「数据竞态」分型的展开打法：「加打印就消失」的 Heisenbug、偶发、多核不一致的识别、定位与根因。
> 本文转录自 spec §4「按症状分型（数据竞态）」+ §5「知识源与优先级」。

**核心原则（先记住）**：数据竞态（data race）是 C 语言层面的定义——两个访问冲突（同地址、至少一写）、并发发生、且至少一个是「普通访问」（非 `READ_ONCE`/`WRITE_ONCE`/锁保护）。它天然偶发、对时序敏感，所以「加打印就消失」。根因是**缺锁 / 缺屏障 / 重排**，修法上**优先加锁**，屏障是最后手段。

## 工具一：KCSAN —— 数据竞争报告怎么读

**识别什么症状**：偶发崩溃或错值、多核结果不一致、加一条 printk 或换编译选项后问题消失（Heisenbug）。

**关键 config**：`CONFIG_KCSAN=y`（GCC/Clang 均需 ≥ 11）。采样式动态竞态检测器，靠编译器插桩 + 软 watchpoint，按概率抓现行，无假阳性但可能漏报（unsound）。

**怎么读输出**：典型报告：

```
BUG: KCSAN: data-race in 写函数 / 读函数
write to 0xADDR of 8 bytes by task 487 on cpu 0:
  <写侧调用栈>
read to 0xADDR of 8 bytes by task 488 on cpu 6:
  <读侧调用栈>
value changed: 0x... -> 0x...
```

按顺序读：

1. **header**：`in A / B` 点出冲突的两个函数。
2. **两个访问点栈**：`write to ... by task X on cpu N` / `read to ... by task Y on cpu M`，各带完整调用栈——把这两段栈和代码对照，即定位「谁在哪一行并发访问了同一地址」。
3. **access type**：`write`/`read`（至少一写）；地址后 `of N bytes` 是访问宽度。
4. **是否被锁保护**：KCSAN 只对「普通（plain）访问」设 watchpoint；若两侧都用了 `READ_ONCE`/`WRITE_ONCE`/锁/`atomic_*`，则不会报。所以「报了」说明至少一侧是裸访问。
5. `value changed:` 显示观察到的旧值→新值（额外佐证真改了）。
6. **unknown origin 报告**（`race at unknown origin`）：只看到一侧、另一侧未知（对方没被插桩或来自 DMA），必带 `value changed`；由 `CONFIG_KCSAN_REPORT_RACE_UNKNOWN_ORIGIN`（默认开）控制。

**调参**：`kcsan.skip_watch`（每 CPU 跳过的内存操作数，越小越易抓）、`kcsan.udelay_task` / `kcsan.udelay_interrupt`（watchpoint 后延迟，越大竞态窗口越大）；运行时 `echo on/off > /sys/kernel/debug/kcsan`。弱内存建模 `CONFIG_KCSAN_WEAK_MEMORY=y` 可检测缺 `smp_mb/wmb/rmb` 的重排型竞态。严格模式 `CONFIG_KCSAN_STRICT=y` 贴近 LKMM。

## 工具二：内存序基础 —— 何时需要屏障 / `READ_ONCE` / `WRITE_ONCE`

**识别什么症状**：代码「看起来有锁」但仍偶发；发布-订阅模式里 flag 已置位但数据没跟上；跨 arch 表现不一致（x86 正常、ARM 出错）。

**关键原语**：

- `READ_ONCE(x)` / `WRITE_ONCE(x, v)` —— 标记「这是一次并发访问」，阻止编译器合并/拆分/重排这次访问、防 store/load tearing（如 64 位写被拆成两次 32 位）。**并发访问的变量必须成对使用**，漏一个编译器就可能出花活。
- `smp_wmb()`（写屏障，order 写）、`smp_rmb()`（读屏障，order 读）、`smp_mb()`（全屏障，order 读写）—— 在 CPU 层面禁止指定的重排。
- `smp_store_release()` / `smp_load_acquire()` —— 发布/订阅的成对屏障，比裸 `smp_wmb`+`smp_rmb` 更语义化。
- `data_race(expr)` —— 标注「此处有意竞态、我已评估安全」，让 KCSAN 忽略该访问。

**什么时候必须 `WRITE_ONCE`/`READ_ONCE`**：

- 一个变量被多核/中断/NMI 并发访问，而访问没被同一把锁完整保护。
- 发布-订阅：`WRITE_ONCE(data, ...)` 后 `smp_store_release(&flag, 1)`；读者 `smp_load_acquire(&flag)` 后再读 data，否则 data 可能读到旧值。
- 防 tearing：对大于字长的并发写，裸写可能被拆。

## 常见根因 + 修复注意

**常见根因**：

- **缺锁**—— 两个路径访问同一共享变量，没加同一把锁（或锁加得不全）。
- **缺屏障**—— 有锁但顺序语义不够，或发布/订阅忘了 release/acquire 配对。
- **编译器重排**—— 编译器把普通访问合并/拆分/重排（`READ_ONCE`/`WRITE_ONCE` 缺失）。
- **CPU 重排**—— 弱序 CPU（ARM/PowerPC）对普通访问可乱序，x86 强序掩盖了问题。
- **跨 arch 内存序差异**—— x86 强序上「碰巧对」，换 ARM 弱序就错（魔改树尤其常见，见 spec「第 0 步」跨 arch 内存序检查）。

**修复注意**：

1. **优先加锁**—— 明确「这把变量归哪把锁管」，所有访问路径都持锁，竞态自然消失。这是正解。
2. 别随手加 `smp_mb()` 掩盖问题——屏障治标不治本，且屏障语义极易用错、难维护；只有确认是「无锁算法的顺序问题」才上屏障。
3. 需要无锁时，用 `READ_ONCE`/`WRITE_ONCE` + 明确的 release/acquire 配对，并写清注释说明顺序语义。
4. 加 `data_race()` 前想清楚：它只是「告诉检测器闭嘴」，不等于「没有 bug」。
