# 01 内存问题排查

> 崩溃细分里「内存生命周期」分支的展开打法。内核魔改最常见的故障类别：越界、UAF、double-free、未初始化、slab 邻居写坏。
> 本文转录自 spec §4「崩溃细分」+ §5「知识源与优先级」。

**核心原则（先记住）**：内存类故障的 oops 现场是受害者，根因在内存生命周期历史里。代码阅读在原理上找不到根因，必须靠运行时工具把"受害者地址"翻译回"凶手地址"。运行时客观事实是最高优先级知识源（spec §5 优先级 1）。

> 本文件只覆盖「写坏内存」（损坏型：越界/UAF/double-free/未初始化）。「用光内存」（耗尽/OOM）见 `methodology/12-OOM与内存耗尽.md`，「该释放没释放」（泄漏）见 `methodology/13-内存泄漏kmemleak.md`。

## 工具一：KASAN —— 越界 / UAF / double-free

**识别什么症状**：oops 现场地址落在某个 slab 对象附近但代码看起来没错；或怀疑数组越界、释放后仍被访问（UAF）、同一块内存被释放两次（double-free）。

**关键 config**：
- `CONFIG_KASAN=y`（通用版 `CONFIG_KASAN_GENERIC`，x86 默认；另有 `CONFIG_KASAN_SW_TAGS` / `CONFIG_KASAN_HW_TAGS`）。
- 配合 `CONFIG_KALLSYMS` 解析符号、`CONFIG_DEBUG_INFO` 出完整栈。

**怎么读输出**：KASAN 报告形如 `BUG: KASAN: slab-out-of-bounds in <function>` / `use-after-free in <function>` / `double-free`，关键在它给出两段栈：一段是**坏访问栈**，另一段是 `Allocated by:` / `Freed by:` —— 后者就是"凶手"（谁分配的、谁释放的）。把 Allocated/Freed 栈与业务逻辑对照，即定位生命周期断裂点。

> 出处：`Documentation/dev-tools/kasan.rst`

## 工具二：KMSAN —— 未初始化内存

**识别什么症状**：行为随编译/时机变化、结果偶发对错、数值读到"垃圾值"；KASAN 不报（不是越界/UAF，而是值本身未初始化）。

**关键 config**：`CONFIG_KMSAN=y`（依赖 Clang，x86_64）。

**怎么读输出**：KMSAN 报 `BUG: KMSAN: uninit-value in <function>`，并给出 **origin 栈**（未初始化值是在哪里诞生的），直接指向漏初始化的分配/转换点。

> 出处：`Documentation/dev-tools/kmsan.rst`

## 工具三：page_owner + mm tracepoints —— 谁分配的 / 什么状态

**识别什么症状**：想知道某块内存（尤其某页）是被谁、在哪个调用栈、以什么掩码分配的；或跟踪页的生命周期流转（分配 → 使用 → 释放 → 再分配）。

**关键 config**：`CONFIG_PAGE_OWNER=y`，启动参数 `page_owner=on`；tracepoints 走 `/sys/kernel/tracing/events/`（kmem / vmscan / mm_page_alloc 等事件组）。

**怎么读输出**：
- page_owner：读 `/sys/kernel/debug/page_owner`，每条给出「Page allocated via order X, mask ..., pid/tgid/comm + 分配栈」，把物理页翻译回分配者。
- mm tracepoints：`perf` / `trace-cmd` 挂 kmem 事件，看页/对象的分配与回收时序。

> 出处：`Documentation/mm/page_owner.rst`（v6.6；v5.10 为 `Documentation/vm/page_owner.rst`）；tracepoints 见 `Documentation/trace/`

## 工具四：slub_debug / SLAB poisoning —— slab 邻居写坏

**识别什么症状**：某个对象被越界写，破坏了相邻对象的内容；或怀疑某对象写了它边界之外的红区（红区越界）。这类"邻居写坏"往往是另一个对象越界写到这个对象。

**关键 config**：`CONFIG_SLUB_DEBUG=y`，启动参数 `slub_debug=ZP`（Z=redzone 红区检测、P=poisoning 毒化；加 `U` 记录分配/释放者）。

**怎么读输出**：破坏点在释放或下一次访问时被毒化/红区校验抓到，报 `SLAB` 对象损坏 / `Redzone` / `Poison overwritten` 之类，配合 `U` 给出的 `Allocated by / Freed by` 栈定位是谁写的。

> 出处：`Documentation/mm/slub.rst`（v6.6；v5.10 为 `Documentation/vm/slub.rst`）；启动参数见 `Documentation/admin-guide/kernel-parameters.rst`
