## 引源白名单（只从这些源引）

| 优先级 | 源 | 说明 |
|--------|----|----|
| 1（最高） | 运行时客观事实 | KASAN 报告、crash dump、tracepoint 数据；无出身歧义 |
| 2 | 当下代码本身 | 唯一确定在跑的；但"为什么"不在代码里 |
| 3 | git / provenance（当线索） | 上游可信；魔改不可靠 |
| 4（最低） | Documentation | 过时、不覆盖魔改，可能误导 |

白名单五类：

1. 内核 `Documentation/`（dev-tools、trace）
2. Bootlin 调试培训
3. McKenney perfbook / LPC 演讲
4. LKML / lore
5. syzbot 报告

> patch 中心，不是文档中心：魔改树文档滞后、不覆盖改动，所以把上游 patch / syzbot 报告看得比 Documentation 更重。

## 研究出处（§8.4）

- **superpowers**：`systematic-debugging`（先根因后修复、不猜）、`verification-before-completion`（证据先于结论）、`test-driven-development`（先测试后修复）。
- **Reflexion**（arXiv:2303.11366）：失败转具体可执行反思 + 客观验证器。
- **Tree of Thoughts**：多路径 + 显式回溯。
- **Epistemic Lock-in**（https://openreview.net/pdf?id=hMptycsA60 ）：信息视野缩小、失败解释同质化、停止生成新假设。
- **progress mirage / loop engineering**：自评分不可信。

> 这条元方法同样工具无关，写进 AGENTS.md 让任何 Agent 都遵守。
