# 定位及解决总结：<一句话标题>

> 本文件是**可选的复盘正文**（长）。与 `kb/_template.md`（经验教训，必填、短）不同，这里记录一次完整定位过程的证据链与推理，供后续同类问题回溯。
> 写完本文件后，务必把「经验教训」抽一条填入 `kb/_template.md` 并入库（经验教训必填）。

## 1. 背景

- 现象是什么（oops 签名 / 挂死 / 行为错 / 性能劣化）。
- 触发条件：什么负载、什么版本、单机还是多机、偶发还是必现。
- 影响范围：哪个子系统、哪个功能。

## 2. 定位过程（证据链，按时间）

> 严格记录「每一步用了决策树哪个分支、哪个工具、读到了什么、排除了什么」。这是复盘最有价值的部分。

1. **症状分型**：按 `methodology/00-决策树.md` 第 1 步，归到七类中的哪一类。
2. **第 0 步判定**：这段是上游原生还是魔改？（决定 git/文档可信度）
3. **用了哪些工具**（按最小扰动顺序）：先读了什么（oops/dmesg/源码），再埋了什么检测器（KASAN/KCSAN/lockdep/kmemleak），最后才 printk。
4. **关键证据**：贴出决定性的输出（KASAN 的 `Allocated by/Freed by` 栈、lockdep 的 `->` 环、kmemleak 的分配栈、ftrace 的卡点等），并说明「它证明了什么、排除了什么」。
5. **走过的弯路**：哪条路是死胡同，为什么，怎么换的思路（对应「死胡同换思路」约束）。
